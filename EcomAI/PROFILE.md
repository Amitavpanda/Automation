## 6. Tally Strategy (Migration On-Ramp)

EcomAI is **not a Tally replacement**. It is the intelligence + commerce layer that makes Tally irrelevant by making it invisible.

| Tally does | EcomAI does (Tally doesn't) |
|---|---|
| Desktop-only accounting | Public B2B storefront + mobile app for retailers |
| Single-branch P&L | Multi-branch consolidated P&L in real time |
| No communication | WhatsApp collections, reminders, campaigns |
| No AI | Credit risk scores, dead stock alerts, daily summaries, warehouse anomalies |
| No reconciliation | Auto-reconciliation (Shopify + gateway + ledger) |
| No storefront | Branded store with cart + credit-limit validation |
| No mobile | PWA for retailer self-service |
| Manual follow-up | Automated collections escalation |

### Tier A — Existing Tally users (anchor clients)
Keep Tally running 90 days, bidirectional XML sync:
1. **Month 1:** Tally sync live. Ledgers, stock, P&L visible Day 1. AI dashboard, WhatsApp, storefront on existing data.
2. **Month 2–3:** Native entry screens (payment/receipt/invoice vouchers). Client enters data in EcomAI, not Tally.
3. **Month 4:** Drop Tally entirely. Save ₹18K–54K/yr renewal. EcomAI becomes single platform.

**Tier A pitch:**
> "You keep Tally running for 90 days. On Day 1, your data is already in EcomAI. You get AI insights, WhatsApp collections, and a mobile storefront your retailers will love — things Tally will never build. By Day 90, you won't open Tally anymore. You save Tally's renewal cost. EcomAI replaces it."

### Tier B — New customers (no Tally)
- Never see Tally. Work natively on EcomAI's accounting engine.
- Same UI, same DB schema, same reports — `tally_sync: false` flag.
- EcomAI is single source of truth for ALL customers. Tally sync is only a migration bridge.

### Tally Technical Facts
- Tally exposes HTTP XML server (port 9000). Send XML → Tally executes → returns XML.
- XML API (read/write): masters, ledgers, P&L, Balance Sheet, vouchers, GST invoicing, opening balances, real-time sync.
- ODBC (read-only): BI dashboards only, can't write back.
- EcomAI already has Tally XML importer (`src/server/integrations/tally/`) — file upload, chunking, mapping, idempotency via `tally_guid` / `tally_voucher_number`.
- **Local connector** (same LAN as Tally, port 9000) for live XML ↔ EcomAI. Cloud app can't reach `localhost:9000`.

### Architecture Principles
- EcomAI DB is single source of truth. Tally sync is a bridge, not the store.
- Write path branches on `tally_sync`: true → EcomAI DB + push XML to Tally; false → EcomAI DB only.
- Read path identical for both tiers — same reports, same UI.
- Idempotency keys: `tally_guid` (masters), `tally_voucher_number` (orders), `reference` (ledger payments).
