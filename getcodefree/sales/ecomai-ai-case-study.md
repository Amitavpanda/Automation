# EcomAI — AI-Powered Commerce OS

## Case Study: Building a Production-Grade AI Platform in 2 Months

---

### The Challenge

Micro-businesses in India need accounting, credit management, collections, and operational insights — but can't afford a full CA team. Existing tools are disconnected, manual, and don't talk to each other.

### The Build

**Tools**: Cursor + Claude Code as primary development environment
**Timeline**: Concept → production MVP with real users in 2 months
**Stack**: Python, FastAPI, Node.js, React Native, Postgres, Docker, Redis, Stripe, Twilio

### What We Built

**AI CA Assistant** — An AI layer over each business's complete data (sales, purchases, payments, inventory). Merchants ask natural language questions — "What's my outstanding this month?", "Who hasn't paid in 60 days?", "What was my profit last quarter?" — and get answers that previously required a chartered accountant.

**Agentic Credit & Collections** — Multi-agent system that:
- Tracks credit limits and aging automatically
- Sends personalized payment reminders via WhatsApp/SMS
- Escalates to human intervention only when exceptions arise
- Reduced manual follow-up work by ~80%

**AI Layer on Every Business Element** — Classification, enrichment, and generation pipelines across catalog, orders, payments, and inventory. Commerce infrastructure where AI is not a feature — it's the operating system.

### Production Reality

- **4 active businesses** running daily operations on the platform
- Live at [ecombharatai.com](https://ecombharatai.com)
- Merchants onboarding in under 5 days
- Full-stack B2B/B2C: website, mobile app, backend, AI workflows

### Why AI-Native Tooling Mattered

Cursor and Claude Code compressed what would have been a 6-month roadmap into 2 months. Every part of the stack — from schema design to agent orchestration to frontend — was built with AI-assisted development. Not as a novelty, but as muscle memory.

The same approach that shipped EcomAI.
